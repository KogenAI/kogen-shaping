# Time and parallel work

The shaping has a time target for all rounds together: {{budget}} minutes is the usual guidance and {{upper}} minutes is the upper end of the performance target. Each round's text states the elapsed time and the target. Crossing the target is never a stop, but converge inside it: submit a complete package in the first rounds, well inside the target. Once the elapsed time stated in the round is within about 3 minutes of the usual target of {{budget}} minutes or past it, submit the best complete package you have and spend later rounds only on the refusals Kogen names, with no new exploration of files you have not read. A late package is still checked by every ordinary gate.
Issue independent reads, searches and commands together rather than one at a time.
For broad reading across many files, you may run several read-only subagents in parallel on a fast model (for example Sonnet or Haiku) and ask each for the specific facts you need, with file and line references; write the package itself in the main session. Do not use subagents for small lookups the main session can do directly.
Read what the request and its acceptance need, not the whole repository; stop exploring once the package can be written.
