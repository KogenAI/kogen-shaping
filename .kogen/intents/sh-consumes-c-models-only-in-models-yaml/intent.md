# Follow the coordinator's models-file-only lineup

Slug: sh-consumes-c-models-only-in-models-yaml

Acceptance:

kogen-coordinator's change c-models-only-in-models-yaml (commit `d74daae36f56d4e195d6ff04e79e74eab1530bb7`, "Read model roles only from the models files", the producer's new main) changed a contract this repository uses, on purpose, with no compatibility layer. Under it `project.LoadConfig` takes every model role only from the defaults, then `.kogen/models.yaml` (when present), then `.kogen/local/models.yaml` (when present), each role a file names replacing the whole role; `project.ParseConfig`/`LoadConfig` refuse a root `models:` key in `.kogen/project.yaml` as `environment/project_config_invalid` (exit 3), Detail the file, with the one line `line <N>: models is no longer read from .kogen/project.yaml; move the model lineup to .kogen/models.yaml`; a models file must be a root mapping whose only key is `models` (roles indented under it), validated with the role rules (a bad role is `environment/project_config_invalid`, exit 3, Detail `<root>/.kogen/models.yaml`). `Template()` and `RenderConfig` write no `models:` block. This repository follows that contract; there is no fallback and no test or code accepts the old behaviour.

Today (pin `v0.0.0-20261105022408-e7bc7ce9c169`) the tests put `models:` in `.kogen/project.yaml`, and the shape test helper `lineupFiles` (shape/helper_test.go) picks the place through `lineupInModelsFile`, which detects an older candidate coordinator by the reason `models_moved` and then writes the roles unindented without the `models:` root key, which the new coordinator also refuses. Against the new main the tests listed in the request fail with `environment/project_config_invalid`. Production code needs no behaviour change: it reads roles only through `cfg.Models` from `project.LoadConfig` (a scratch run of the whole `./shape` package against d74daae passed once the helper below wrote the lineup as the new contract requires).
