# Require evidence for a Shape environment stop

Slug: k-shape-environment-stop-evidence
Model: not applicable — two counters already kept in the submission loop (invalid submissions and environment-only refusals); one precedence rule between them, stated below with an example and exercised by the scenarios
Acceptance:

- features/steps/k-shape-environment-stop-evidence__harness.js

Today Shape ends with `environment/shape_environment` (exit 3, "shaping cannot go on without something only your environment can provide; nothing was asked or published") because the question check model put every question of a submission in the class `environment`. Nothing asks whether the Intent and its acceptance could be written and run without the thing. The stop also fires on spent retries: `shape/question.go` stops when `sh.environmentRefusals >= 2 || sh.priorInvalid >= submissionRetryLimit(...)-1`, so after two refusals of any class, one environment question on the last attempt ends shaping as an environment fault. The refusal feedback for `environment` tells the shaper that asking again ends Shape, so the shaper can leave the loop by relabelling a question. After this change an environment stop needs evidence that the question check judged, a question needed only in production leads to a recorded Decision, and spent retries are reported as spent retries. The general mechanism is the existing question check (`questionClassify`/`questionGate` in `shape/question.go`) with the cited text passed in. No phrase of a question is matched. This applies to both the native and the external shaper, since both go through `questionGate`.

**Citations in a question.** A question's text may cite what this shaping read or ran. It uses the marker grammar of Decisions (`evidenceCitations`, `splitCitation`, `parseEvidenceItem` in `shape/evidencemark.go`): `(evidence: <repository path>)` or `(evidence: ran `<command>`)`, with items separated by "; ". The question text is kept verbatim everywhere: in the question check input, the feedback and the stop's lines. The shaper's `submit` schema, its prompts and the policy goldens (`shaper_policy_golden.json`, `prompts_golden.json`, `defs_golden.json`) do not change.

**Question check input.** If no question cites a nonempty item, the input stays byte-identical to today. Otherwise `"\n\n# Cited evidence\n\n"` is appended after the `# Questions` section, followed by one block per nonempty cited item (questions in order, then their items in order). The blocks are joined by `"\n\n"`, and trailing newlines are removed from each shown text:
- a file the native shaper read: `Question <n> cites <path> (read by this shaping):` + newline + the text of this shaping's latest `read_file` call of that cleaned path. This applies when the path does not end in `/`, is tracked at HEAD, and the main conversation called `read_file` on it;
- a command a native probe ran: `Question <n> cites ran `<command>` (probe output):` + newline + the text of this shaping's latest probe of exactly that command;
- for the external shaper, a file tracked at HEAD (and not a directory), when the session inspected anything: `Question <n> cites <path> (read from the checkout):` + newline + that file's checkout text, numbered as `read_file` numbers it;
- otherwise one line: `Question <n> cites <item as cited>: not shown (<reason>)`. The reason is one of `<path> is not a file tracked at HEAD`, `this shaping did not read <path>`, `this shaping's session read nothing, so <path> was not read`, `no probe of this shaping ran `<command>`` or `Kogen keeps no output of the external session's commands`.
The exact shape is in acceptance scenarios 2 and 3.

**Question check classes.** A new class, `environment_prerequisite`, goes between `environment` and `repository_fact` in `questionClasses` and in the tool's enum. `questionInstructions` changes in two ways: its "You see only ..." sentence now names the cited evidence, and the `environment` line is narrowed and followed by the `environment_prerequisite` line. The exact text is in scenario 3 ("question_check_instructions"). Only `ui_ux` and `handoff` still reach the user.

**Feedback.** The refusal headline and the instructions for the other classes stay. `questionInstruction("environment")` becomes the "record a Decision and continue: ..." text of scenario 1. `environment_prerequisite` gets the "the cited evidence shows ..." text of scenario 3. A question classed `environment_prerequisite` with no shown citation gets the `environment` instruction instead.

**Environment stop.** An *evidenced environment-only submission* is a questions submission whose every question the check classes `environment_prerequisite` and whose every question has at least one shown citation. The first one in a run is refused like any other refused question submission: it counts as an invalid submission, and its feedback is the `environment_prerequisite` instruction. The second one in the run ends Shape with the unchanged `environment/shape_environment` error, exit 3 and message. Nothing is asked or published, and the submission is still recorded as `submission_refused` at gate `question_check`. For each question in order, the error lines are:
- `- <question text>`;
- `  blocks: <the check's why>`;
- `  evidence: <its shown items as cited, joined by "; ">`.
No other submission ends Shape as an environment fault. That covers `environment` questions, prerequisites with nothing shown, mixed submissions, and any submission on the last attempt. The `sh.priorInvalid` clause is removed. Precedence: the stop is decided in the question gate before the invalid-submission limit. With the default limit of 3, evidenced environment-only submissions at attempts 2 and 3 stop as an environment fault at attempt 3. One evidenced submission at attempt 3, after two refusals of other classes, ends as spent retries.

**Spent retries.** Shape ends at the invalid-submission limit with `shape/invalid_output: the shaper's output was not a valid Intent after <N> attempts` (or `intent/not_ready` when files were proposed). In either case, if the run's question checks refused at least one question, the error gains a last line `question check refusals: <class> x<count>[, <class> x<count>...]`: each refused question counts once per refusal, and the classes are in the order of their first refusal (for example `question check refusals: product_policy x2, environment x1`). The earlier lines (the last refusal's problems and the earliest unresolved refusal) stay before it. A run with no question-check refusal ends with exactly the error it has today.

The k-shape-decide-non-ux-general files are not edited (scenario 7).

## Decisions
- An environment stop requires evidence the question check judged: the shaper's cited read or run text is passed into the question check, which alone decides whether that text is about the named item and shows it needed and not optional or stood in for (source: request)
- A question about an item needed only to run the finished feature in production, or one already stood in for, is refused with "record a Decision and continue" and never ends Shape (source: request)
- The stop keeps `environment/shape_environment`, exit 3 and its message, fires on the second evidenced environment-only submission of the run as today's two-submission stop, and adds the blocks and evidence lines (source: request)
- Spent retries keep their existing `shape/invalid_output` error and gain a last line listing the question-check refusal classes with counts (source: request)
- Questions cite evidence in their text with the evidence marker grammar of Decisions (assumption: the request leaves the citation form open; the existing marker keeps the shaper's submit schema and policy goldens unchanged) (source: request)
- The external shaper's command citations are shown as not retained (assumption: Kogen receives no output of the external session's Bash calls, only that one ran) (source: request)
