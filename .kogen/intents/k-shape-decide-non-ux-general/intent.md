K-SHAPE-DECIDE-NON-UX-GENERAL (kogen-delivery, 3 Nov 2026, on the owner's binding ruling via main and the research audit SHAPING-AUDIT-20261103: shaping changes are general mechanisms only, and nothing from outside a task's own spec and app reaches the shaper; change_type: fix; follows K-SHAPE-DECIDE-NON-UX, landed 37d5474). The landed principle stays: the shaper decides every non-UX question itself, and only open UI/UX questions and mandatory authentication or security handoffs reach the user. Its acceptance fixtures mirrored held-out benchmark tasks, so this change replaces them with an invented, neutral fixture (an orchard frost alarm) that proves the same acceptance, and deletes the landed acceptance files that carried the old fixture. It also tightens what a Decision may rest on: a Decision's `(evidence: ...)` is accepted only when this shaping actually read the cited file, listed the cited directory or ran the cited command; where evidence is absent or conflicting, the shaper records the uncertainty it decided under with the existing `(assumption: ...)` marker, and the approval card always lists such Decisions so the approver can confirm or reverse them before approving, instead of seeing them presented as certain.

Today (`shape/evidencemark.go`) a cited path passes when it is tracked at HEAD, even if the shaper never opened it; the question check and evidence feedback never mention recording uncertainty; and the approval card lists `(assumption: ...)` Decisions only when the opt-in `shape_decision_check` is enabled (`assumptionLines` in `shape/decision.go`). Everything else of K-SHAPE-DECIDE-NON-UX stays as landed: the question check (when it runs, its instructions, input text, tool definition, classes, per-class lines, refusal counting and the `environment/shape_environment` fault), the evidence marker syntax and where its gate runs, the empty-item, untracked-path and command problem lines, the decision check, the native `ShaperInstructions()` bytes, the main tool list, ordinary native request bytes and the external shaper's stable text. No CLI command, flag, option or configuration key is added, and no timeout, limit or retry is added or raised.

## Decision evidence must have been read or run
- Gate and order: unchanged (`evidenceProblems`/`evidenceGate`, in `checkSubmission` for a files submission, after the data-stores gate and before the opt-in decision check, step self-check and readiness). Decisions are numbered as today. For each item, in decision and item order, the first matching problem applies:
  1. a blank item: `- decision <n>: an empty (evidence: ...) item` (unchanged);
  2. a `ran `<command>`` item: the existing native `- decision <n>: no probe of this shaping ran `<command>`` and external `- decision <n>: this shaping's session ran no command, so `<command>` was not run` lines (unchanged; a probe counts once called, whatever its result);
  3. a path not tracked at HEAD: `- decision <n>: <path> is not a file or directory tracked at HEAD` (unchanged);
  4. new, native Shape, a cited file (a path not ending in `/`): `- decision <n>: this shaping did not read <path>` unless a `read_file` call of this Shape run's main shaping conversation had a `path` argument equal to the cited path, both compared after Go's `path.Clean` of the trimmed text (so `./lib/sensors.js` matches `lib/sensors.js`), whatever that call returned;
  5. new, native Shape, a cited directory (a path ending in `/`): `- decision <n>: this shaping did not list <path>` unless a `list_files` call of this Shape run's main conversation had a `path` argument (cleaned the same way; a missing or empty path is the whole repository, `.`) equal to the directory, an ancestor of it, or `.`;
  6. new, external Shape (`executor: claude-code`), where Kogen sees which tools ran but not their paths: `- decision <n>: this shaping's session read nothing, so <path> was not read` when the shaper's session reported no completed, non-denied read-only inspection tool call (the `executor_tool` events that `inspectedBy` already accepts: Read, Glob, Grep, LS or Bash).
- `search_text` calls, probes and Shape worker (`shape_batch`) reads do not count as reading a cited path; a probe that printed a file is cited as `ran `<command>``. Reads accumulate over the attempts of one Shape run, like probes; a resumed Shape run (after answers) starts with none.
- The refusal headline becomes exactly: `Decision evidence: <N> problem(s) with what the Decisions cite; nothing was published. A Decision's (evidence: ...) names files this shaping read or directories it listed, tracked at HEAD, or ran `<command>` for a command this shaping ran, separated by "; ". Where the repository has no evidence or conflicting evidence, mark the Decision (assumption: <the uncertainty you decided under>) instead. Resubmitting this candidate unchanged is refused again.` The rest of the refusal (problem lines joined by single newlines, gate `decision_evidence`, one `submission_refused` event, the shared invalid-submission counter, nothing published) is unchanged.
- Kogen checks that the cited file was read, the directory listed or the command run in this shaping. It does not prove that what was read supports the Decision, and on external Shape it cannot match the path or command text.

## Recording the uncertainty a Decision was made under
- The question check refusal headline becomes exactly: `Question check: <R> of <N> question(s) are not UI/UX choices left to the user; nothing was asked. Investigate and decide each one yourself: read the repository or run a probe, then record a Decisions line that cites what you read or ran before its source tag, as - <decision> (evidence: <repository path>) (source: request) or - <decision> (evidence: ran `<command>`) (source: request). Where the repository has no evidence or conflicting evidence, record the uncertainty you decided under instead, as - <decision> (assumption: <the uncertainty>) (source: request); the user confirms or reverses it at approval. Ask the user only UI/UX questions that the request and the answers leave open, or a mandatory authentication or security handoff.` The per-question lines are unchanged.
- The approval card (`kogen intent approve <slug>` without a hash, and the moved-base card) lists every `## Decisions` line that contains `(assumption:` under its existing `Assumptions to confirm` block, as today without the leading `- ` and the trailing source tag, whether or not `shape_decision_check` is enabled. Without such a line the block is absent, as today. The decision check itself, its headline and its own marking are unchanged.
- Kogen does not classify which unmarked Decision is the shaper's own non-UX choice: the refusal feedback above, the read-or-run gate and the existing opt-in decision check are the mechanisms; an unmarked Decision is not refused by this change.
