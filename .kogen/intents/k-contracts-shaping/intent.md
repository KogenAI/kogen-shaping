# Pin kogen's use of shaping in a contract suite

Slug: k-contracts-shaping
Model: not applicable — the change adds a test suite and its README; kogen-shaping's behaviour and state are unchanged
Acceptance:
- .kogen/intents/k-contracts-shaping/acceptance.feature
- features/steps/k-contracts-shaping__steps.js
- features/steps/k-contracts-shaping__plants.js
- features/steps/k-contracts-shaping__control.js

Today a kogen-shaping landing runs its consumer kogen's offline suites to catch interface breaks; that is slow, and what kogen relies on is written down nowhere in kogen-shaping. kogen-shaping gains a `contract/` suite that pins exactly what kogen uses: the exported API it calls, the behaviours it relies on and the formats it reads. The cases are copied from kogen-shaping's own tests that kogen's tests exercise, adapted to the exported API and made self-contained with synthetic fixtures. The suite is a normal test package, so the configured `go-test` check (`GOFLAGS=-trimpath go test ./...`) and the landing gate's `go test -race ./...` run it: an interface change fails in kogen-shaping first. It is fast: its package run time in `go test -count=1 ./contract/...` stays within 60 seconds. An intended interface change then edits this contract together with the paired kogen items.

Nothing else changes: `shape/`, `cmd/`, `go.mod` and `go.sum` stay byte for byte as committed at HEAD, `.kogen/project.yaml` is unchanged, no command, flag, option or production timeout is added or raised, and the existing `shape` tests (including `shape/response_budget_test.go`, which kogen also runs by name) stay as they are. `README.md` may gain one bullet naming `contract` in its Packages list; nothing else in it changes. The suite never reads or imports kogen or any other consumer repository.

### Consumer evidence (kogen 9bf6073, the only consumer)

- `cli/engine.go` calls `shape.Shape(ctx, s, shape.ShapeInput{Project, Slug, Request, RequestPath, Tools, InstallRoot, Client, External})`, `shape.Refine(ctx, s, shape.RefineInput{Project, Slug, Hash, Request, RequestPath, Tools, InstallRoot, Client, External})` and `shape.Approve(ctx, s, shape.ApproveInput{Project, Slug, Hash, By, Tools})`; `cli/facts.go` calls `shape.Preflight(ctx, s, shape.PreflightInput{Project, Slug, JSON, Checkout})`. `s` is a `*sys.Session` (kogen-loop `sys`), `ctx` a `context.Context`. Each returns `(exit code int, error)` and kogen maps the exit code to its own process exit. `Tools` is a kogen-verification `verify.Tools`, `Client` a kogen-loop `*provider.Client`, `External` kogen's optional external executor (`shape.External`).
- `cli/response_budget_test.go` runs `TestShapeBudgetRolesShape` and requires these subtests to pass: "shape sends every request under thirty minutes and records it once", "a stalled shape expires unavailable naming thirty minutes, is not retried and records once", "refine sends every request under thirty minutes and records it once", "a stalled refine expires unavailable naming thirty minutes and records once". `cli/assembly_test.go` only lists the module path.
- Out of scope: `shape.Init` (moving to kogen-setup; absent at HEAD), the shape-workers subtest "shape workers send under the same thirty minutes within the one record", shape workers and the `shape_batch` tool (removed from shaping by f04edce; `shape_batch` answers "unknown tool"). The suite covers only what shaping provides today.

### The suite

`contract/` is one Go package (`package contract`) made only of `_test.go` files, plus `contract/README.md`. No non-test Go file, no subpackage, no build constraint, no `t.Skip`, no `time.Sleep` or other wall-clock wait. It uses only kogen-shaping's exported API: it imports the standard library, `github.com/KogenAI/kogen-shaping/shape` and packages of the Kogen dependency modules go.mod already requires (for example `kogen-loop/provider`, `kogen-loop/sys`, `github.com/KogenAI/kogen-coordinator/project`, `.../git`, `.../durable`, `github.com/KogenAI/kogen-verification/verify`, `github.com/KogenAI/kogen-executor/executor`). It never imports `net` or `net/http/httptest`, opens no listener and starts no server: there is no network. Every file it writes is under `t.TempDir()`. Tests run in parallel and pass deterministically under `go test -race -count=1 ./contract/...`; no test raises a timeout. The package's run time, as `go test -count=1 ./contract/...` reports it on its `ok` line, is at most 60 seconds (observed: the four copied subtests take about 3.4 s in `shape/`, and with the Approve and Preflight cases about 5.6 s under `-race`).

1. **API pins (compile time).** With the types written out:
   - `shape.Shape`, `shape.Refine`, `shape.Approve` and `shape.Preflight` are each assignable to `func(context.Context, *sys.Session, <its input>) (int, error)`, e.g. `var _ func(context.Context, *sys.Session, shape.ShapeInput) (int, error) = shape.Shape`.
   - Every input field kogen sets is assigned from a variable of its type, so a changed field name or type fails to compile: `ShapeInput{Project, Slug, Request, RequestPath, InstallRoot string; Tools verify.Tools; Client *provider.Client; External shape.External}`; `RefineInput` the same plus `Hash string`; `ApproveInput{Project, Slug, Hash, By string; Tools verify.Tools}`; `PreflightInput{Project, Slug string; JSON bool; Checkout any}`.
   - `shape.External` and `func(project.Role) (executor.Executor, error)` are assignable to each other.
   Nothing else exported by `shape` is pinned.
2. **`TestShapeBudgetRolesShape`**, copied from `shape/response_budget_test.go`, with exactly the four subtests named above (verbatim names) and the same assertions, all through `shape.Shape`/`shape.Refine` with a fresh session per run and no `ResponseBudget` configured:

A rerun of the same Shape with a fresh session then returns a nil error, more than one shaper request has been sent in all, and the events file holds two `response_budget` events.

4. **Self-contained fixtures**, copied from `shape/helper_test.go`, `shape/refine_test.go`, `shape/response_budget_test.go`, `shape/loop_knobs_test.go` (`knobText`) and `shape/main_test.go`, adapted to the exported API (the earlier attempt failed because its copy answered every request with HTTP 400 and shaping stopped before the behaviour under test):
   - *Scripted provider*: an in-process `http.RoundTripper` set as the client's `HTTP` (`&http.Client{Transport: …}`), which records each request's context deadline and answers on the Responses wire. A request whose `tools` offer (as `name` or `function.name`) `submit_decision_check` is answered with that call and `{"items":[]}`, `submit_contract_review` with `{"findings":[],"environment":[]}`, `submit_contract_confirmation` with `{"verdicts":[]}`; these do not consume the case's script. Every other request takes the case's next scripted turn; past the script it answers HTTP 400 `{"error":{"code":"invalid_request_error","message":"scripted failure","type":"invalid_request_error"}}`. A turn is `text/event-stream` frames `data: <json>\n\n`: one `{"type":"response.output_item.done","output_index":i,"item":…}` per item, then `{"type":"response.completed","response":{"id":"resp-<n>","model":"gpt-6.1-sol","reasoning":{"effort":"high"},"usage":{…}}}` with the usage the shape fixture sends; items are `{"type":"function_call","call_id":…,"name":…,"arguments":"<JSON text>"}`. A files `submit` turn first calls `read_file` of `README.md` (an uninspected Shape cannot publish). The stall answers 200 `text/event-stream` whose body read advances the client's clock (`Client.Now`) by 30 minutes and 1 second and then fails (for example `io.ErrUnexpectedEOF`). The session's `KOGEN_PROVIDER_URL` is a loopback origin such as `http://127.0.0.1:9` that is never dialed.
   - *Fixture project*: as `newShpFx`/`newRefFx`: a Git repository in `t.TempDir()` with a local user, an empty hooks path and `commit.gpgsign=false`; `.gitignore` `.kogen/local/\n`, `README.md`, `calc.js`, `features/steps/calc_steps.js`, `.kogen/project.yaml` `version: 1\ncommands:\n  checks: [{name: unit, run: 'true'}]\n  acceptance: {run: sh accept.sh, steps_dir: features/steps}\n` and an `accept.sh` that replays a prepared Cucumber message report (red: each scenario's last step failed, exit 1; green: all passed, exit 0), committed. The submitted package is the `is-even` `intent.md`, `acceptance.feature` and `features/steps/is-even__steps.js` of `shpFiles`; the acknowledgment resubmits the feature whole. A ready draft is that package written, its readiness recorded with `verify.Readiness.Check`, and for the refine cases `.kogen/local/readiness/is-even.json` then removed. HOME is a `t.TempDir()` with `.kogen/credentials/chatgpt.json` (`access_token`, `refresh_token`, `client_id` `oaiapp_fixture`, `expires_at` a day ahead). The client is `&provider.Client{Cache: provider.NewCache(nil), Sleep: <returns nil at once>}`; the session is `sys.NewWith(env, root)` with buffered stdout and stderr; env is the process environment without `GIT_*`, plus `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`, `HOME` and `KOGEN_PROVIDER_URL`.
   - *TestMain*: resolves `KOGEN_NODE` (kept when it is an executable file, else the absolute path of `node` on PATH) and, when `KOGEN_CUCUMBER` is unset, sets it to `../testdata/tools/cucumber/node_modules` when that exists, as `shape/main_test.go` does: Shape's step check runs Node and Cucumber on the submitted step file. It may also skip durable syncs (`durable.SkipSyncInTests`) and use the git wrapper as that TestMain does.
5. **`contract/README.md`**: what the suite pins and the consumer evidence above (kogen 9bf6073), an inventory with one row per pinned item (`shape.Shape`, `shape.Refine`, `shape.Approve`, `shape.Preflight`, each input type and its fields, `shape.External`, `TestShapeBudgetRolesShape` and each subtest, the Approve and Preflight cases) naming the tests that assert it, how to run it (`go test -race -count=1 ./contract/...`), its isolation, what is out of scope and why, and the rule that an intended interface change edits this contract together with the paired kogen items.

### Acceptance

Scenario 1 runs `go test -race -count=1 ./contract/...` in the checkout and requires an `ok` line for `github.com/KogenAI/kogen-shaping/contract` (not `[no tests to run]`), a test-only package without the `net` and `net/http/httptest` imports, a README naming the four entry points and `TestShapeBudgetRolesShape`, and `shape`, `cmd`, `go.mod`, `go.sum` as at HEAD. Scenario 2 runs `go test -count=1 ./contract/...` (the ordinary check's mode) and requires the package's `ok` line to report a run time of at most 60 seconds. The outline plants, in a scratch copy of the checkout (without `.git`, `node_modules` and `.kogen/local`), one change to kogen-shaping's production code at a time, each altering behaviour kogen reaches through `shape.Shape` or `shape.Refine` on the path its budget tests exercise, and requires `go build ./...` and `go vet ./...` to pass there and `go test -count=1 ./contract/...` to fail with a failing test (not a build or setup failure): the budget recorded twice by Shape, recorded twice by Refine, a ten-minute `ResponseBudget` set by Shape, Shape returning exit 1 for every refusal, Refine setting its error's `Exit` to 1. Each plant's exact text is in `features/steps/k-contracts-shaping__plants.js`. Go commands run offline (`GOPROXY=off`, `GOFLAGS=-mod=readonly -buildvcs=false -trimpath`, `GOWORK=off`) without the caller's `GIT_*`/`KOGEN_*` settings, with `KOGEN_NODE` and `KOGEN_CUCUMBER` from the caller (else this Node and `testdata/tools/cucumber/node_modules`).

## Decisions
- kogen-shaping keeps a `contract/` test suite pinning exactly what kogen uses of it: the exported API, the behaviours it relies on and the formats it reads, derived from kogen's calls and the tests it runs, with synthetic fixtures only (source: request)
- The suite is part of the ordinary `go test ./...`, so an interface change fails in kogen-shaping first; no consumer suite runs and no consumer repository is read at test time (source: request)
- The suite is fast: its package run time in `go test -count=1 ./contract/...` is at most 60 seconds (source: request)
- `shape.Init`, shape workers and `shape_batch` are left out (source: request)
- No model runs, no network, no new command or flag, no timeout raised (source: request)
- Every planted change alters behaviour kogen reaches through the exported API on its tests' path and leaves every package compiling (source: request)
- An intended interface change edits the contract together with paired consumer items; `contract/README.md` states this rule (source: request)

## Tests
- kogen's calls of Shape, Refine, Approve and Preflight with the input fields it sets keep compiling with the same types: compile-time pins in the new `contract/` package (unit)
- Shape and Refine send every request under thirty minutes and record the budget once; a stalled Shape or Refine expires unavailable naming thirty minutes after one request with exit 4, and a Shape rerun records again: `TestShapeBudgetRolesShape` and its four subtests in `contract/`, plus acceptance outline plants 1–5 (integration)
- Approve shows the card with exit 5, approves with exit 0 recording the By approver, and refuses a non-repository with exit 3: an Approve test in `contract/` (integration)
- Preflight's JSON document is exit 0 with the given checkout and five passed checks for an approved draft, and exit 3 with the configuration error without `.kogen/project.yaml`: a Preflight test in `contract/` (integration)
- The suite is a test-only package without network imports that passes under the race detector in the checkout, with a README naming what it pins: acceptance scenario 1 (integration)
- The suite is fast enough for the ordinary check, at most 60 seconds of package run time: acceptance scenario 2 (integration)
- Production code, go.mod and go.sum are unchanged and the existing shape tests keep passing: scenario 1's HEAD check and the configured go-test check (existing)
