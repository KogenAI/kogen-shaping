# Treat unreaped zombies as gone in kill-group test

Slug: fix-k-shape-kill-group-zombie
Model: not applicable — a test-only fix of one liveness predicate and one new test; no product state or interacting rules change
Acceptance:
- .kogen/intents/fix-k-shape-kill-group-zombie/acceptance.feature
- features/steps/fix-k-shape-kill-group-zombie__steps.js
- features/steps/fix-k-shape-kill-group-zombie__harness.js
- features/steps/fix-k-shape-kill-group-zombie__control.js

`consumes/kogen-loop/sys_test.go` TestKillGroupOnExit decides that a process of the command's group is still running with `syscall.Kill(pid, 0) == nil`. `kill(pid, 0)` also succeeds on a zombie: a process that has exited but that its parent has not reaped yet. When the test runs under a parent with PR_SET_CHILD_SUBREAPER set (the Linux Build supervisor sets it), the group member that KillGroupOnExit killed is reparented to that subreaper and stays a zombie until the subreaper reaps it, so every Linux Build failed with `process <pid> of the command's group is still running after Run`. This change makes the test count such a zombie as gone, keeps the test failing when a group member really keeps running, and adds a Linux test that reproduces the subreaper condition in a child process. Only test code and the package README change; no production code, no other package, no kogen-loop code, no timeout or limit.

What the Build changes, all in `consumes/kogen-loop/`:

1. Liveness. TestKillGroupOnExit's `alive` predicate becomes a "running" predicate used for both of its checks: a process is running when `syscall.Kill(pid, 0) == nil` and it is not a zombie. Where `/proc/<pid>/stat` can be read (Linux), the process is a zombie when the state field — the first field after the last `)` of that file — is `Z`. Where it cannot be read (macOS has no /proc), `kill(pid, 0)` alone decides, as now. No sleep, poll, retry or wait is added: the predicate is evaluated once, exactly where `alive` is evaluated now. The two checks keep their meaning and messages: after Run with `KillGroupOnExit: true` the left-behind process must not be running (`sys.Options.KillGroupOnExit: process %d of the command's group is still running after Run`), and after Run without the option it must still be running (`... without the option process %d must outlive its command`). The kill-group check itself (the `leaveBehind` command, both Runs, both checks) moves into a helper that TestKillGroupOnExit and the new test both call.
2. New test `TestKillGroupOnExitUnderChildSubreaper`, one top-level test function compiled on every platform (not in a build-tagged file), so `go test -list .` lists it everywhere:
   - On any GOOS other than linux it calls `t.Skip` at once.
   - On Linux, in the test process itself (parent mode), it never calls prctl. It re-runs the test binary (`os.Args[0]`) as a child with `-test.run=^TestKillGroupOnExitUnderChildSubreaper$`, `-test.count=1` and `-test.v`, and an added environment variable that marks child mode. That variable must not start with `KOGEN_` or `GIT_` (TestMain unsets those); use `CONSUMES_KILL_GROUP_CHILD=1`. The parent fails, with the child's combined output in the message, unless the child exits 0 and its output holds `--- PASS: TestKillGroupOnExitUnderChildSubreaper`. The parent writes the child's output only through `t.Log`/`t.Error`/`t.Fatal` messages, never directly to its own standard output.
   - In child mode it first calls `prctl(PR_SET_CHILD_SUBREAPER, 1)` and fails if that fails, then runs the kill-group helper. The child does not reap the processes orphaned to it, so the group member that KillGroupOnExit killed stays a zombie of the child during the check. The prctl call lives in a Linux-only test file (`//go:build linux`) through `syscall.RawSyscall(syscall.SYS_PRCTL, 36, 1, 0)`: 36 is PR_SET_CHILD_SUBREAPER, which the syscall package does not define on linux/amd64. A `//go:build !linux` counterpart keeps the package compiling elsewhere.
   - It names no kogen-loop identifier that is not already in the README inventory.
3. Follow-up note. kogen-loop's own `contract/sys_test.go` TestRunKillGroupOnExit has the same weakness: its `waitGone` polls `kill(-pgid, 0)` until ESRCH, which an unreaped zombie in the group never gives. That repository is not edited here; a Go comment next to the new running predicate names `contract/sys_test.go` and `TestRunKillGroupOnExit` as the kogen-loop follow-up.
4. `consumes/kogen-loop/README.md`: the inventory rows of `sys.Options.KillGroupOnExit` and `sys.Session.Run` add `TestKillGroupOnExitUnderChildSubreaper`; the "Running" paragraph no longer says "Nothing is skipped" — it says that TestKillGroupOnExitUnderChildSubreaper runs only on Linux and is skipped elsewhere, and that under a child subreaper a kill-group check waits for kogen-loop's sweep (about 6 s); the "Isolation" paragraph adds the test binary re-run as a child and the reading of `/proc/<pid>/stat` of a process the test's own command started.

Under a non-reaping child subreaper, kogen-loop's sweep still waits about 6 s (its 5 s SIGTERM-to-SIGKILL interval plus its 1 s group wait), because `kill(-pgid, 0)` keeps succeeding while the zombie is in the group; that is kogen-loop's pinned behaviour and stays unchanged. Measured as in the request: plain runs take about 0.1 s.

## Decisions
- A process that has exited but is not yet reaped (a zombie) counts as gone; a process that keeps running still fails the check. (source: request)
- The subreaper test sets PR_SET_CHILD_SUBREAPER only in a child process, runs the kill-group check there, and is skipped on platforms other than Linux; the existing check without a subreaper stays. (source: request)
- The new test is one top-level test function that skips off Linux, and the child is the test binary re-run on that same test; there is no separate helper test function. (source: request)
- The kogen-loop follow-up is recorded as a Go comment in this package; no other repository is edited. (source: request)

## Tests
- A killed group member that is an unreaped zombie counts as gone (Linux, non-reaping child subreaper): new TestKillGroupOnExitUnderChildSubreaper and acceptance scenario 1, which reproduces the reported failure on the unfixed tree (regression)
- A group member that keeps running still fails TestKillGroupOnExit and the new test: acceptance scenario 2 with a kogen-loop copy that leaves the group running (integration)
- The new test is skipped on platforms other than Linux: acceptance scenario 1 off Linux (integration)
- The existing check without a holding subreaper passes and the test process itself does not become a subreaper: TestKillGroupOnExit with unchanged expectations and acceptance scenario 3 (existing)
- The README inventory and Running paragraph name the new test, and the kogen-loop follow-up is noted: acceptance scenario 4 (integration)
