# Keep Shape submittable after prose and refusals

Slug: k-shape-submit-reachable
Model: not applicable — one existing counter of the native Shape loop is reset at each submission and the stop text gains its cause; the worst-case bound follows from the existing invalid-submission budget and is exercised end to end by the finite-bound scenario
Acceptance:

K-SHAPE-SUBMIT-REACHABLE (research, 3 Nov 2026; Terra AoR priority). Native Shape (`shape/shape.go` `converse`, `shape/force.go`) today ends `shape/invalid_output: the shaper answered without calling any tool 3 times (no-tool limit); no submission was made` once three tool-free answers have accumulated anywhere in the conversation, never reset by a refusal or by progress. Prose turns far apart (one before the first submit, one after each refusal) add up, the third one ends the run on an unforced turn (the inference after a refused submission carries no forcing), so a submit-forcing inference after the last refusal is never tried. The stop names only the protocol symptom ("ended without calling submit", "no submission was made" even after refused submissions), and `provider_call` events carry usage only, so the text of those answers is lost. On the adopted release with Terra (medium) this is the most frequent shape failure (4 of 12 control cells).

This change, in native Shape only:
1. **No-tool count since the last submission.** The no-tool limit (`noToolLimit = 3`) counts the tool-free answers since the shaper's last submit call, or since the start when it has made none. Every submit call that does not end the conversation starts a new count: a refused submission at any gate (it is an `outInvalid` result: validation, question check, decision evidence, readiness not-ready, contract review and the others that record `submission_refused`) and a submission answered with readiness failures for acknowledgment (`outObservations`). The conversation ends at the no-tool limit when that count reaches 3. Everything else is unchanged: after every tool-free answer the next inference requires `submit` at API level where the route supports it (`provider.SupportsToolChoice`) and carries the existing reminder `End by calling submit with either questions or files.`; the inference after a refused submission is not forced (so the shaper can still read before repairing); the invalid-submission budget (`submissionRetryLimit`, default 3) and its stop `the shaper's output was not a valid Intent after 3 attempts` (or `intent/not_ready` once files were written) are unchanged and decided at the submit call. Because a stop needs three tool-free answers since the last submission, at least two inferences after the last refusal followed a tool-free answer (forced where the route can force) before any stop.
2. **Finite bound kept.** Between two submissions at most two tool-free answers occur unless the third ends the run, and refused submissions are bounded by the invalid budget. A conversation that only answers in prose, with or without refused submissions, therefore ends after at most 3 + 2 × (limit − 1) tool-free answers: 7 tool-free answers and 9 requests with the default limit 3 (prose, prose, refusal, prose, prose, refusal, prose, prose, prose).
3. **Actionable stop text.** At the no-tool limit Shape ends with exit 1, class/reason `shape/invalid_output` and detail and lines (rendered by `sys.Error.Render` as the detail line followed by two-space-indented lines) by the last submission of the run:
   - none: detail `the shaper answered without calling any tool 3 times (no-tool limit); no submission was made` (unchanged);
   - refused: detail `the shaper answered without calling any tool 3 times since its last submission (no-tool limit); that submission (attempt <n>) was refused at gate <gate>`;
   - readiness failures returned for acknowledgment: detail `the shaper answered without calling any tool 3 times since its last submission (no-tool limit); that submission (attempt <n>) returned readiness failures that were not acknowledged`.
   The lines are, in order: `the shaper ended without calling submit` (unchanged first line); for a refusal `last refusal (attempt <n>, gate <gate>):` followed by its problem lines exactly as recorded in its `submission_refused` event (at most 20 lines, each at most 300 characters); for readiness failures `last submission (attempt <n>): readiness failures returned for acknowledgment, see <path>`, where `<path>` is the observations file of that submission relative to the project root (`.kogen/local/shaping/<slug>/observations-<request>.txt`); and last `last tool-free answer: <first line>`, the recorded text of the final tool-free answer (point 4) up to its first newline, or `(empty)` when that answer had no text. `<n>` is the submission's attempt number as in `submission_refused` (`attempt`, the run's count of submit calls) and `<gate>` the gate name recorded there. The 3 in the details is `noToolLimit`.
4. **Tool-free answer text retained.** Every native Shape response without a tool call records, right after it is received and before the run decides to stop or continue, one event in the shaping events file (`.kogen/local/shaping/<slug>/events.ndjson`): `{"event":"tool_free_answer","owner":"shape","request":<r>,"no_tool_turns":<t>,"chars":<c>,"truncated":<bool>,"text":"<text>"}`. `request` is the run's main shaping request number (the `kogen: shaping (request <r>, ...)` number); `no_tool_turns` the cumulative tool-free answers of the run including this one (the same count `forced_submit_turn` and `shaping_turn_counts` report). The text is the `text` of every `output_text` part of every assistant `message` item of the response, in order, joined with `\n` (the provider client normalizes Responses, Chat Completions and Anthropic answers to such items), redacted with `verify.NewRedactor(<session environment>, <session HOME>).Redact` (the same masking as other retained evidence: secret-named environment values, Kogen's saved credentials, labeled secrets such as `token=...`), then trimmed of surrounding whitespace. `chars` is its length in Unicode code points; `text` is its first 2000 code points; `truncated` is `chars > 2000`. When `chars` is 0 (for example a response with only a reasoning item) the event has no `text` key. Nothing else is recorded about the answer; `provider_call` events are unchanged.

Unchanged and out of scope: Refine (`submit_refinement`, its cumulative no-tool count, its stop text and events), external Shape (claude-code, which has no no-tool limit), the reminder texts, `forced_submit_turn`, `shaping_turn_counts` and the working-window handoff fields (their `no_tool_turns` stays cumulative), ordinary native request bytes (`shape/testdata/force_ordinary_golden.json` is not regenerated), the invalid-submission budget and its stop text, and every gate. No configuration key, flag, option or limit is added or raised. Benchmark evidence and the held-out screen stay with research (not part of this Build): research screens the landed candidate on its held-out set before adoption. Acceptance here is synthetic only.

The Build updates the existing tests whose expectations encode the replaced behavior: `TestShapeForceNoToolBound` "counters are independent" (it pins that a refusal does not reset the count, which this request replaces; it becomes an equivalent test that a submission starts a new count: read, prose, refusal, prose, prose, then the forced inference's valid submit is accepted) and its `shape` and `reset/shape` subtests (the `reset/shape` conversation starts with a refused submission, so its detail becomes the refused-at-gate detail; the `shape` lines gain `last tool-free answer: three`), and `TestShapeWithoutSubmitIsAskedToEndWithSubmit` (lines gain `last tool-free answer: done`).

## Decisions
- A conversation does not end at the no-tool limit while no submit-forcing inference has been tried after the last refusal: the no-tool count restarts at every submission that does not end the run, and the forced inference still follows every tool-free answer (source: request)
- When Shape still cannot end with a valid submit, the stop states the last cause the shaper was asked to fix (gate and problem text of the last refusal, readiness failures to acknowledge, or no submission) and the first line of its last tool-free answer (source: request)
- The text of every tool-free answer is retained in the shaping events, redacted like other evidence, bounded at 2000 characters, without text when empty (source: request)
- A conversation that keeps answering in prose stops after a finite number of inferences (source: request)
- Acceptance is synthetic only; benchmark evidence and the held-out screen stay with research (source: request)

## Source comparison
- Addressed: Problem 1 (cumulative count pinned by "counters are independent") by point 1 and the replaced test with its stated reason (request Synthetic acceptance 7); Problem 2 and 3 (no forcing after a refusal, ceiling hit on an unforced turn) by the count restarting at each submission, so a stop is always preceded by forced inferences after the last refusal; acceptance "Prose and refused submissions alternate, then the forced inference submits" (request scenario 1: request 6 is forced and its valid submit is accepted; today the run ends at request 5).
- Addressed: Problem 4 (wrong cause) by point 3; acceptance "The stop names the gate and problem of the last refusal" (request scenario 3), "The stop names readiness failures left unacknowledged" and "A shaper that only answers in prose stops with its last answer" (request scenario 2).
- Addressed: Problem 5 and the Need on retained text by point 4; acceptance "Tool-free answer text is redacted, bounded at 2000 characters and absent when empty" (request scenario 5), plus the Responses and Chat Completions "normal" scenarios.
- Addressed: request scenario 4 (no regression of the normal path) by "Prose before a valid submit keeps the normal outcome and records the prose" (3 requests, exit 0, as today); request scenario 6 (routes without API tool forcing) by the two `anthropic` scenarios, where no request is forced and the reminder is the only enforcement; the safety Need by point 2 and "Prose answers between refused submissions still end after a finite number of inferences" (9 requests).
- Decided: forcing is not added to the inference after a refusal (request mechanism 2 lists its absence as a cause but the Need asks only that a forced inference be tried before a stop); restarting the count achieves that and keeps ordinary request bytes and the shaper's ability to read before repairing. Readiness feedback also restarts the count because it is a submission the shaper is asked to act on, and the stop names it.
- Kept unchanged: the invalid-budget stop `the shaper's output was not a valid Intent after 3 attempts` already lists the last refusal's problem lines; Refine, external Shape and the force golden are out of scope.
- Retained as context only: evidence cells stctl-st-r1 (Studio, adopted 573d023, Terra medium), lmctl-lm-r1, the dsscreen arms and the 1526-file aggregate (24 at the no-tool ceiling, 21 after two refused submissions; 43 on the invalid budget with no prose), and the verbatim stop texts quoted above; they are research evidence, not executable acceptance.
