# Let Shape repair a package before resubmitting

Priority P1 (coherent set shapes 1/9). Native Shape (`shape/shape.go` `converse`, `shape/force.go`) today makes every inference that follows a tool-free answer require the terminal `submit` tool where the route can force a tool (`provider.SupportsToolChoice`), with the reminder `End by calling submit with either questions or files.`. When a shaper answers a refused submission, or readiness failures returned for acknowledgment, with prose such as "the fixture still needs investigation", the next inference cannot read, probe or propose. It can only submit the incomplete package or repeat the rejected one, consume an attempt and return to the same prose. Reaching submit does not show that anything was repaired. The final stop names only the last refusal (for example only `acceptance.feature does not exist`), not an earlier technical-question refusal that was never resolved, and an unchanged resubmission is not distinguished from a repaired one.

After this change (native Shape's conversation and Shape's shared submission handling; Refine unchanged):

1. **Recovery inference.** A *repairable submission* is a submit call that did not end the conversation and was either refused at any gate (an `outInvalid` result with its `submission_refused` event) without being an unchanged package (point 2), or answered with readiness failures for acknowledgment (`outObservations`). The first tool-free answer after a repairable submission is followed by one *recovery inference* instead of the forced inference:
   - its request keeps the route's automatic tool choice (`ToolChoice` empty) and the complete tool set (read_file, view_image, list_files, search_text, probe, documentation, propose_files, submit); no `forced_submit_turn` event is recorded for it;
   - instead of the reminder it carries one user message with exactly this text, where `<n>` is the submission's attempt number as in `submission_refused`, `<gate>` its gate, `<problems>` its problem lines exactly as recorded in `submission_refused` (at most 20 lines of at most 300 characters) joined by newlines, and `<path>` the observations file of that submission relative to the project root (`.kogen/local/shaping/<slug>/observations-<request>.txt`):
     - refused: `Recovery before submitting again: submission attempt <n> was refused at gate <gate> and nothing was published. Your accumulated proposals are kept, as the cumulative proposal manifest lists. This inference does not require submit: investigate with read_file, list_files, search_text, probe or documentation, add or correct files with propose_files, then call submit with the repaired package. An unchanged package is refused again. The refusal:` followed by a newline and `<problems>`;
     - readiness failures: `Recovery before submitting again: submission attempt <n> returned readiness failures for acknowledgment (see <path>) and nothing was published. Your accumulated proposals are kept, as the cumulative proposal manifest lists. This inference does not require submit: investigate with read_file, list_files, search_text, probe or documentation, add or correct files with propose_files, then call submit with the repaired package, or acknowledge legitimate missing-feature red as the readiness feedback describes.`
   - before that request is sent Shape records one event in `.kogen/local/shaping/<slug>/events.ndjson`: `{"event":"recovery_turn","owner":"shape","request":<r>,"attempt":<n>,"cause":"refused","gate":"<gate>"}` after a refusal, or `{"event":"recovery_turn","owner":"shape","request":<r>,"attempt":<n>,"cause":"readiness_failures"}`, where `<r>` is the run's main shaping request number of the recovery inference (the `kogen: shaping (request <r>, ...)` number).

   Everything else in the loop stays: the inference right after any submission is unforced; answers with tool calls neither count nor force; every other tool-free answer (before any submission, the second after a submission, any after an unchanged-package refusal) is followed by the forced inference with the existing reminder; the no-tool limit (`noToolLimit = 3` tool-free answers since the last submission), the invalid-submission budget (`submissionRetryLimit`, default 3) and their stop texts stay. The answer before a recovery inference is still a tool-free answer: it records `tool_free_answer` and counts in `no_tool_turns` (`tool_free_answer`, `forced_submit_turn`, `shaping_turn_counts` and the working-window handoff); while a recovery inference is pending the handoff has no `forced_submit_pending`.
2. **Repaired versus unchanged package.** The package of a files submission is the complete set of accumulated proposals (paths and exact contents) right after its files are merged, before any gate. Shape remembers the package of every refused files submission of the run with the attempt that first submitted it. A later files submission with an equal package goes through the same gates as today. When it is refused, its feedback text gains one final line `Unchanged: this package is identical to the one refused at attempt <m>; repair it before submitting again.` (`<m>` that first attempt), and it is not a repairable submission, so no recovery inference follows it. A changed package is checked as today and, when refused, is repairable. Submissions whose files never merge (validation and publication refusals, questions, blocked reports) have no package and never carry the line. The problem lines of `submission_refused`, the not-ready lines and `contract-contradictions.json` are unchanged.
3. **Earliest unresolved refusal in stops.** The unresolved refusals are the refused submissions since the last submission answered with readiness failures, or since the start of the run. When there are at least two and the earliest has a different gate or different problem lines than the last, each stop that reports the last refusal also reports the earliest one, as the line `earliest unresolved refusal (attempt <m>, gate <gate>):` followed by its problem lines as recorded in `submission_refused`:
   - the no-tool stop after a refusal: after the last refusal's problem lines, before `last tool-free answer: ...`;
   - the invalid-budget stops `shape/invalid_output: the shaper's output was not a valid Intent after 3 attempts` and `intent/not_ready: the Intent is not ready to build`: after the last refusal's lines.
   In every other case the stop texts are unchanged. Example (the `question-then-incomplete` journey): a technical question is refused at attempt 1 (gate `question_check`), the Intent-only package at attempt 2 (gate `intent`, `acceptance.feature does not exist`), then three prose answers; the stop lines are `the shaper ended without calling submit`, `last refusal (attempt 2, gate intent):`, `acceptance.feature does not exist`, `earliest unresolved refusal (attempt 1, gate question_check):`, the question's refusal line, and `last tool-free answer: ...`.
4. **Finite bound.** At most three tool-free answers follow any submission (the third ends the run) and at most `submissionRetryLimit` submissions are refused, so prose and refused submissions alone still end within 9 requests at the default limits: `p p R p p R p p p` has forced requests 2, 3, 6 and 9 and recovery inferences 5 and 8 (before, 2, 3, 5, 6, 8 and 9 were forced). Repeating an unchanged package ends at the invalid budget. Answers with tool calls stay uncounted, as in ordinary discovery today.

External Shape (claude-code sessions) is never forced and gets no recovery inference; because it shares the submission handling, its feedback gets the `Unchanged:` line and its invalid-budget stop the earliest block. Unchanged and out of scope: Refine (`submit_refinement`, its forcing, counters and stops); every gate, its decision and its feedback text apart from the appended `Unchanged:` line; the question check (a technical question is refused exactly as today, in or out of recovery; an interface question still reaches the user with exit 5); readiness and acknowledgment; approval; the Shaper's instructions and tool definitions (`shape/testdata/shaper_policy_golden.json`, `prompts_golden.json` and `defs_golden.json` stay byte-identical); ordinary request bytes (`shape/testdata/force_ordinary_golden.json` and `force_ordinary_models_golden.json` are not regenerated). No configuration key, flag, option or limit is added or raised. Acceptance is synthetic only: scripted loopback provider, no live model.

## Decisions
- After a refused changed package or readiness failures, the first prose answer is followed by one inference that does not require submit and carries the concrete feedback with the investigation and proposal tools named; later prose answers still require submit (source: request)
- Accumulated proposals stay retained across recovery, and the cumulative proposal manifest keeps listing them (source: request)
- A resubmission whose complete package equals an earlier refused one is labelled unchanged, is checked and refused as before, and earns no further recovery (source: request)
- Stops keep the final refusal and add the earliest unresolved refusal when it differs (source: request)
- Prose and repeated output still end within the existing no-tool limit and invalid-submission budget; no limit is raised (source: request)
- Acceptance uses a small synthetic repository and a scripted provider without live model calls (source: request)
