Request (P1, owner rule: shaping asks only UX): a technical or security choice can be disguised as a question about what the caller experiences, and after it is settled a continuation can ask an engineering subchoice of the same decision. Retaining question and answer text alone does not retain the shaper's sourced decision, its constraints or why a later question is already settled. Extend the existing non-UX settlement with continuity of sourced decisions across shaping continuations: record each decision with the evidence actually consulted, its constraints and its remaining uncertainty; make it available when later questions are checked and when the final Intent is produced; do not ask a settled decision again because its wording or option granularity changed; keep its source identity across rounds; revise it only on material new evidence that is recorded with the reason; keep absence of evidence an explicit assumption, never an invented citation or an automatic human question. Open presentation or interaction preferences stay questions, and exact approval and the acceptance gates stay in force.

Today Shape keeps only the rounds of questions and answers between its runs (`state.json`). The question check sees the request, the earlier questions and answers and the questions; the evidence gate accepts a Decision's cited file only when the current run read it; nothing a shaper decided before it stopped for a question survives. After this change a shaper records sourced decisions with a submission, Kogen checks their evidence against what this shaping actually read or ran, keeps them in a decision ledger across the shaping's rounds and after publication, shows them to the question check and to the shaper in later rounds, refuses a question a recorded decision settles, requires the Intent to carry every decision that stands, accepts an earlier round's receipt (attributed to that round) for a file that has not changed, and changes a decision only through a revision that cites evidence the current round read or ran. This applies to `kogen intent shape` (packages `shape` and `cmd/kogen-shape`) for the native and the claude-code shaper; their differences are named below. A *round* is one Shape run of a shaping: the number of question rounds in `state.json` when the run starts, plus one (run 1 is round 1; the run that continues after round k's answers is round k+1).

**Submitting decisions.** The `submit` tool definition (`submitDef` in `shape/policy.go`, and so the external shaper's result schema) gains one optional property, `decisions`: `{"type": "array", "description": D, "items": {"type": "object", "properties": {"decision": string, "evidence": list of strings, "constraints": list of strings, "uncertainty": string, "revises": string, "why": string}, "required": ["decision"]}}`, using the file's `str()` and `strList()`, where D is exactly: ``Optional, with questions or files, never with blocked: the technical, security, protocol, storage and limit decisions this shaping made, kept across its continuations. evidence lists repository files this shaping read and ran `<command>` items of probes that succeeded; constraints are the rules the decision imposes; uncertainty states what stays uncertain and is required without evidence; revises names a recorded decision this one replaces, with why it changed and evidence this round read or ran.`` Nothing else of the tool, the prompts under `shape/prompts` or `ShaperInstructions` changes. Evidence items use the existing item grammar (`parseEvidenceItem`): a repository path, or ``ran `<command>` ``. Validation (gate `validation`, as today's validation problems): `decisions` beside `blocked` is the problem `decisions go with questions or files, not with a blocked report`; a `decisions` value that is not a list, an item that is not an object, a blank or missing `decision`, an `evidence` or `constraints` that is not a list of strings, or an `uncertainty`, `revises` or `why` that is not a string is the one problem `decisions: every decision needs decision text, optional evidence and constraints lists of text, and optional uncertainty, revises and why text`. An empty list is the same as no `decisions`. A pre-checked call that is not counted records nothing.

**The decision record gate.** A counted questions or files submission with decisions passes gate `decision_record` right after validation: before the question check for questions, before the publication problems for files. Decisions are numbered 1.. in the submitted order. A submitted decision is *the same* as a ledger decision that stands when its decision, constraints (in order), evidence items (in order, each trimmed), uncertainty, revises and why are equal, an absent field counting as empty; it is kept as it is (same id, round and receipts) without any check. Every other decision is checked; for each, in this order, these problem lines apply:
- no evidence item and a blank uncertainty: `- sourced decision <n>: no evidence and no uncertainty; cite what this shaping read or ran, or state the uncertainty you decided under`;
- a nonblank revises with a blank why: `- sourced decision <n>: revises <id> without why`; a revises that is not the id of a ledger decision that stands: `- sourced decision <n>: <id> is not a recorded decision that stands`;
- each evidence item in order, each giving at most one line. A blank item: `- sourced decision <n>: an empty evidence item`. A path ending in `/`: `- sourced decision <n>: <item> is a directory; cite the files this shaping read`. A path that is not a file tracked at HEAD: `- sourced decision <n>: <item> is not a file tracked at HEAD`. For the native shaper, a tracked file gets a *fresh* receipt when this run's main conversation read it (`readTexts` of its `cleanCitedPath` exists and does not start with `error: `); otherwise a *carried* receipt when the ledger already holds a receipt of that cleaned path whose `sha256` equals the SHA-256 of the file's current checkout bytes (the last such receipt in ledger and item order); otherwise, when the ledger holds only receipts of that path with another digest, `- sourced decision <n>: <item> changed since round <r> read it; read it again` (r the round of the last of them); otherwise `- sourced decision <n>: this shaping did not read <item>`. For the external shaper, whose tool events name no paths, a tracked file gets a carried receipt as above first; otherwise a fresh receipt when its session completed a read-only inspection (`sh.inspected`); otherwise the changed-since line as above; otherwise `- sourced decision <n>: this shaping's session read nothing, so <item> was not read`. A native ``ran `<command>` `` gets a fresh receipt when this run probed exactly that command and the latest answer text starts with `exit status: 0\ntimed_out: false\n`; when that answer starts otherwise, `` - sourced decision <n>: the probe of `<command>` failed (<the answer's first line>), so it is no evidence ``; with no probe of it in this run, a carried receipt when the ledger holds a probe receipt of exactly that item; otherwise `` - sourced decision <n>: no probe of this shaping ran `<command>` ``. An external ``ran `<command>` `` is always `` - sourced decision <n>: Kogen keeps no output of the external session's commands, so `<command>` is no evidence; cite a file this session read ``;
- a revision none of whose items got a fresh receipt: `- sourced decision <n>: revises <id> without evidence this round read or ran, so <id> stands`.

With at least one problem the submission is refused (`sh.refused("decision_record", lines)`, an invalid submission counted like any other), nothing is recorded, asked or retained as a proposal, and the shaper receives the headline ``Sourced decisions: <N> problem(s) with the decisions this submission records; nothing was recorded, asked or published. A sourced decision cites, as evidence items, files this shaping read (or that an earlier round read and that are unchanged since) or ran `<command>` for a probe of this shaping that succeeded; where there is no such evidence, state the uncertainty you decided under instead. A revision names the decision it revises in revises, says why it changed and cites evidence this round read or ran.`` followed by the lines, joined by newlines. Without a problem, every decision that is not the same as a standing one is appended to the ledger, a revision marks the decision it revises as superseded by it, the ledger file is written, and the event `{"event":"decisions_recorded","round":<k>,"recorded":[<new ids>],"kept":[<ids of the same ones>]}` is recorded; then the submission goes on unchanged (question check, or publication problems and the files path).

**The decision ledger.** `.kogen/local/shaping/<slug>/decisions.json`, beside `state.json` (directory 0700, file 0600), is the JSON object `{"version": 1, "decisions": [...]}` written whole. Each decision: `{"id": "D<n>" (n its 1-based position), "round": <round that recorded it>, "decision", "constraints" ([] when none), "uncertainty" ("" when none), "revises" ("" or the id it replaces), "why" ("" when none), "superseded_by" ("" or the id of its revision), "evidence": [receipt...]}`, a receipt per evidence item in order: `{"item": <the item trimmed>, "kind": "read" | "checkout" | "probe", "round": <round of the read or probe>, "sha256": <hex SHA-256 of the file's checkout bytes when the receipt was made; "" for a probe>, "text": <for read, the read_file answer text; for checkout, the file's text numbered exactly as read_file numbers a whole file; for probe, the probe's answer text>}`. A carried receipt is a copy of the earlier one (its kind, round, digest and text). A decision stands while its `superseded_by` is empty; a superseded decision stays in the ledger. A Shape run that starts a new shaping (no `state.json`, after the existing already-shaped check) removes the file first; a continuation reads it (an unreadable or undecodable file fails the run with that error, as `state.json` does); publication keeps it. Only recording writes it.

**The question check.** In `questionInstructions`: the "You see only ..." sentence names "the decisions this shaping recorded with the evidence they cite" before "the questions"; the item sentence asks for "its number, one class, why (one short reason) and decision (the id of the recorded decision that settles it when the class is decided, otherwise an empty string)"; a `decided` line follows `answered`; and the `technical` line names data, storage, limit and security choices "even when it is worded as what the user experiences or chooses". The exact text is in scenario 1 ("question_check_instructions"). `questionClasses` (and the tool's enum) gain `decided` after `answered`; the item schema gains a required string `decision` (scenario 1, "question_check_schema"). Parsing reads a missing `decision` as "" and rejects a non-string one as "an item is malformed". A `decided` item whose decision is not the id of a ledger decision that stands becomes class `technical`, keeping its why. Only `ui_ux` and `handoff` still reach the user. When the ledger holds a standing decision, the check's input gains, between the earlier questions and answers and `\n\n# Questions`, the text `\n\n# Recorded decisions\n\n` followed by blocks joined by `\n\n`: for each standing decision in ledger order its summary and then, for each receipt, `<id> cites <item> <paren>:` and a newline and the receipt text without trailing newlines. A summary is the line `<id> (round <r>): <decision>` followed by the lines `   constraint: <c>` (each), `   uncertainty: <u>` (when not blank), `   revises: <old id> because <why>` (for a revision) and `   evidence: <item> <paren>` (each receipt). `<paren>` is `(read by this shaping in round <r>)`, `(read from the checkout in round <r>)` or `(probe output in round <r>)` by kind, with `; changed since` before the `)` for a file receipt whose digest differs from the file's current checkout bytes. Without a standing decision the input is byte-identical to today. The `question_check` event's item of a `decided` question gains `"decision": <id>`; other items are unchanged. A refused `decided` question's feedback line is `- question <n> (decided): <question> | why: <why> | <id> (round <r>) settles it: <decision>; do not ask it again. Complete the choice from <id>, its constraints and its evidence, and keep it in the Intent's Decisions as: <its Intent line>`. The headline, the other classes' instructions, refusal counting (now also `decided x<n>`) and the environment stop are unchanged.

**Intent lines and the shaper's context.** A decision's *Intent line* is `- <decision> (decision: <id>, round <r>)` + ` (constraint: <c>)` for each constraint + ` (evidence: <items joined by "; ">)` when it has evidence + ` (assumption: <uncertainty>)` when that is not blank + ` (revises: <old id> because <why>)` for a revision + ` (source: request)`. When the ledger is not empty, the shaper's context (`contextBlocks`: the native first message and the external brief) gains, after the earlier questions and answers and before `\n# The Intent to write`, the text `\n# Your recorded decisions (each stands until a revision that cites evidence this round read or ran replaces it; keep every one that stands in the Intent's Decisions exactly as its Intent line shows)\n\n`, then each decision in ledger order as its summary (a superseded one headed `<id> (round <r>, revised by <new id>): <decision>`) with a last line `   Intent line: <its Intent line>` for one that stands, joined by `\n\n`, then `\n`. With an empty ledger the context is unchanged.

**The Intent carries the decisions that stand.** In `checkSubmission`, after the scope refusal and before the evidence gate, gate `carried_decisions` requires, for each standing decision in ledger order, a `## Decisions` line that equals its Intent line once both have their trailing source tag (`sourceTagRe`) removed. Each missing one is the line `- <id> (round <r>) is not in Decisions; keep it as: <its Intent line>`; with any, the submission is refused (invalid, counted) with the headline `Recorded decisions: <N> recorded decision(s) that stand are missing from the Intent's Decisions; nothing was published. A recorded decision stands until a revision that cites evidence this round read or ran replaces it, and its line is kept exactly, before its source tag, so its evidence and constraints stay in force:` and the lines. **The evidence gate accepts carried receipts.** In `evidenceProblems`, a cited tracked file that this run did not read (native) is also accepted when the ledger holds a receipt of that cleaned path with the file's current digest, and for the external shaper such a receipt is used before the inspection rule; a cited file whose ledger receipts all have another digest, and that the native run did not read or the external session did not inspect, is `- decision <n>: <path> changed since round <r> read it; read it again`; a native ``ran `<command>` `` that this run did not probe is accepted when the ledger holds a probe receipt of it. When the gate passes and at least one item rested only on a carried receipt, it records `{"event":"carried_evidence","items":[{"decision":<n>,"item":<item trimmed>,"kind":<kind>,"round":<receipt round>}, ...]}` in decision and item order. No new receipt is made for a carried item.

**Unchanged.** The submission limit and its errors (a run that keeps proposing a settled question ends at the limit with `shape/invalid_output` and the refusal-count line), the other gates and their order, readiness, the decision check, approval and its card, Refine (no ledger, unchanged tools), `cmd/kogen-shape`'s interface, `go.mod`, `.kogen/project.yaml` and earlier Intents' files. No command, flag, setting, timeout or limit is added. The policy, definition and force goldens under `shape/testdata` that change because of the `submit` definition are regenerated only with `go test ./... -update`; the prompts golden does not change. Earlier acceptance that pins the old question check text (k-shape-environment-stop-evidence, k-shape-decide-non-ux-general) is superseded on that text and not edited.

## Decisions
- Decisions are recorded with a submission as structured `decisions` items, not inferred from question or Intent text, so the evidence, constraints and uncertainty are kept as given and checked item by item (evidence: shape/shape.go; shape/policy.go) (assumption: the request leaves the recording form open; a new optional submit property changes the submit definition and its goldens) (source: request)
- A receipt is valid only for a successful read_file of a tracked file in this run, a probe of this run whose answer starts with exit status 0 and timed_out false, an external session that inspected something, or an earlier round's receipt of a file whose bytes have not changed, so an unread file or a failed probe never stands in as evidence (evidence: shape/evidencemark.go; shape/shape.go) (source: request)
- The external shaper's command output is no evidence, because Kogen receives only that a Bash call ran (evidence: shape/external.go) (source: request)
- The ledger lives beside state.json under .kogen/local/shaping/<slug>/, is reset by a new shaping and kept after publication, so the decision and its receipts stay attributable to their rounds (evidence: shape/shape.go) (assumption: the request names no location; the private shaping folder keeps it with the other shaping records) (source: request)
- A question a recorded decision settles is classed decided by the existing question check model, which is shown the decisions with their evidence; Kogen does not match question wording (evidence: shape/question.go) (source: request)
- A decided answer that names no standing decision is treated as technical, so it is still refused and never reaches the user (assumption: a malformed reference should not end shaping or ask the caller) (source: request)
- A revision needs evidence the current round read or ran and keeps the revised decision on record as superseded; without it the old decision stands and the refusal says so (evidence: shape/shape.go) (source: request)
- The Intent must carry each standing decision's exact line, so a later candidate cannot drop or weaken its constraint to reach readiness (evidence: shape/shape.go; shape/evidencemark.go) (source: request)
- Repeated settled questions end within the existing three-submission limit with the existing error and refusal-count line; no new limit is added (evidence: shape/question.go) (source: request)
