# Split work that cannot fit one review

Slug: k-shape-split-oversized-review
Model: not applicable — one deterministic, stateless estimate inside the existing submission loop; its refusals reuse the existing refusal record and bounded correction loop
Acceptance:
- .kogen/intents/k-shape-split-oversized-review/acceptance.feature
- features/steps/k-shape-split-oversized-review__steps.js
- features/steps/k-shape-split-oversized-review__harness.js

Today `kogen intent shape` can publish an Intent whose review cannot fit the review ceiling: its scope check (`shape/scope.go`, run by `checkSubmission` in `shape/shape.go`) estimates only the bytes of the Intent package, and a staged plan only divides that estimate into per-stage units that each carry the whole package. Studio issue 4dfdd67a reports three Builds whose review prompts were 565 KB, 594 KB and 633 KB against the 524288-byte ceiling; they were split and ended review_invalid or usage_limit, after hours of build time.

After this change Shape estimates the mandatory review material of the Intent as one review, before the Intent can be approved, and never publishes an Intent it estimates will not fit. When the estimate is over the ceiling the candidate is refused and the shaper splits the work into separately reviewable Intents: it narrows this Intent to its first part and declares every remaining part in a `## Split` section, and each part must itself fit. The estimate and the ceiling appear in the shape output. The ceiling is unchanged.

Estimate, in bytes, of one Intent (the Intent as written and formatted by the check, and the checkout's HEAD):
- Intent package: intent.md, every path under `Acceptance:` in listed order, and the model file when the Model line declares one, each counted once at the byte length of its written content.
- Review inputs: `README.md` at HEAD (0 when absent) and the testing rules, counted as the byte length of `agent.Prompt(agent.TestingRules)`. Every review carries them.
- Changed files: the files the Intent names. A span is the text between a pair of single backticks on one line (Go regexp "\x60([^\x60\n]+)\x60", matched left to right; a fence of three backticks matches nothing). A span names a changed file when its text equals exactly the path of a blob in the HEAD tree (as `git ls-tree -r -l HEAD` lists it), is not under `.kogen/`, is not `README.md` and is not an Intent package path. Each counts its size at HEAD, once, in order of first appearance; the whole file size is the upper bound of its diff. A path that is not at HEAD (a file the Build adds) is not counted here: an added step file is in the package. The Intent's own changed files are named outside its `## Split` section.
- Estimate = package bytes + review input bytes + changed file bytes. Scenarios are those `project.CheckIntent` returns (an outline counts once per Examples row); acceptance harnesses are the `Acceptance:` paths other than the feature (`intent.StepFiles()`); areas are the distinct directories (`path.Dir`) of the changed files.

The ceiling is `tools.InputBudgetBytes` as compiled in (kogen-loop's `provider.InputBudgetBytes`, 524288 bytes, the limit of one review). Do not copy its value into a shaping constant. The boundary follows decision D7: an estimate equal to the ceiling fits, one byte more is over.

Split section: a `## Split` heading in intent.md followed by bullets `- <slug>: <what the part delivers>`, where the slug is 3 to 48 lowercase letters, digits or dashes; other lines of the section are ignored. A part's changed files are the files named by the same span rule in its bullet text. A part's estimate is the review inputs plus those changed file bytes; its own package does not exist yet and is not counted. The section ends at the next `## ` heading. A `## Stages` plan does not change any estimate: the unit is always the whole Intent, because the final review carries every stage. Shape does not create the other Intents: each remaining part is shaped on its own.

Refusal: when the Intent estimate is over the ceiling, or when the estimate of any part is, the candidate is refused and nothing is published. The result is the lines of the over-ceiling units followed by the guidance line, joined by "\n". The Intent unit (when over) comes first, then each part (when over) in listed order:
- Intent unit line: `Scope check: the Intent is estimated at <E> bytes of mandatory review material (scenarios <S>, acceptance harnesses <H>, changed files <F> in areas <A>), over the <L>-byte review ceiling (tools.InputBudgetBytes).` Then one item line per package file in the order above, `- <path>: <n> bytes (Intent package)`; then `- README.md: <n> bytes (review input)` and `- docs/testing-rules.md: <n> bytes (review input)`; then one per changed file in first-appearance order, `- <path>: <n> bytes (changed file, area <dir>)`.
- Part unit line: `Scope check: part "<slug>" is estimated at <E> bytes of mandatory review material (changed files <F> in areas <A>; its own package is not counted), over the <L>-byte review ceiling (tools.InputBudgetBytes).` Then the two review input lines and the part's changed file lines as above.
- Guidance line, exactly (one line, between the fences):

```
Above the ceiling this cannot be approved as one Intent: split the work into separately reviewable Intents. Narrow this Intent to its first part so that its estimate fits, and list every remaining part in a ## Split section of intent.md, one bullet per part, `- <slug>: <what the part delivers>`, naming in backticks the files that part changes; a part's estimate is the review inputs plus those files, and each part must fit the ceiling too. A ## Stages plan does not lower the estimate, because the final review carries every stage. Do not satisfy the ceiling by deleting requested behaviour: every behaviour and example the request asks for stays in this Intent or in a part. Resubmitting this candidate unchanged is refused again.
```

The refusal uses the existing path: `submission_refused` with gate `scope` and the result's lines as its problems (the existing record bounds apply), an invalid outcome, the existing "Unchanged:" note for an identical package and the existing `intent/not_ready` end when the correction allowance runs out. It runs where the scope check runs now: in `checkSubmission`, after the package is written and formatted and after the contract refusal lookup, before the decision check and readiness, so a refused candidate costs no decision check, contract check or readiness run.

Shape output: for every candidate whose package can be counted, the scope check writes one progress line (stderr, through the shaping progress line writer, which appends " (<s> s)"): `kogen: review estimate <E> bytes of the <L>-byte review ceiling (tools.InputBudgetBytes)`. When that candidate fits and its `## Split` section declares n >= 1 parts, it writes a second progress line, `kogen: split: this Intent is part 1 of <n+1>; shape the other parts as their own Intents: <slug> (<P> of <L> bytes), ...`, with the parts in listed order and <P> their estimates. A candidate with no parts gets no split line. Stdout, the published Intent and the standalone JSON are unchanged.

Removed or replaced: the package-only estimate, the per-stage units of the scope check (a valid `## Stages` plan no longer divides anything), the "one review" and "named files" wording of the unit and item lines, and the staged-plan guidance line. Not changed: the Shaper's prompt, policy and tool definitions (shape/prompts and the goldens `shape/testdata/shaper_policy_golden.json`, `prompts_golden.json` and `defs_golden.json` and the force goldens stay byte-identical; do not regenerate them), the staged-plan format and its parsing, the other gates and their order, Refine, `kogen intent approve`, the review stage and the Build.

## Decisions

## Source comparison
- Addressed, Need 1 (estimate the mandatory review material, changed files plus fixed review inputs, before approval): the Estimate rules and the five scenarios. The estimate runs in Shape's submission loop, so no Intent that Shape publishes is over the ceiling; Refine and `kogen intent approve` are unchanged. Interpretation: the changed files are the files the Intent names in backticks at HEAD, because the Intent states no other list of them; the review inputs are the README and the testing rules.
- Addressed, Need 2 (split into separately reviewable Intents and say so): scenario 2 (an Intent of two large named files is refused, then narrowed to the first with the second as a part, and published with the split shown), scenario 3 (a part over the ceiling is refused; two parts that fit are published) and scenario 4 (a staged plan with one file per stage does not make the Intent fit). Interpretation: "separately reviewable Intents" is this Intent plus the declared parts; each part is shaped on its own, so the other Intents' packages do not exist yet and a part's estimate excludes its own package.
- Addressed, Need 3 (the ceiling unchanged): `tools.InputBudgetBytes`, 524288 bytes, observed in every scenario by the harness and compared with the ceiling in each progress line.
- Addressed, Acceptance 1 (over the ceiling is not approved as one Intent and the split has each part under it): scenarios 2 and 3. Acceptance 2 (under the ceiling is approved as before): scenario 1, which publishes with the same route; scenario 5 pins the boundary (the estimate equal to the ceiling fits, one byte more is refused). Acceptance 3 (the estimate and the ceiling appear in the shape output): the progress lines in scenarios 1, 2, 3, 4 and 5 and the refusal result in scenarios 2, 3 and 4.
- Superseded, not edited: the completed Intents k-shape-size-for-one-review (per-stage units, named files at HEAD size, "one review" wording) and k-shape-scope-gate-counts-package (package-only estimate, named files not counted) encode the scope check this Intent replaces. Their records stay as written; their acceptance is not run with this one. This Intent returns to counting the changed files the Intent names, which the second one removed, because the Studio Builds that overran the ceiling were small Intents over large changed files.
- Known limits, not claimed exhaustive: only files named in backticks and present at HEAD are counted, so an Intent that does not name its files is under-estimated; the real review also carries the diff and check results, which the estimate does not model; a whole named file over-states a small diff. A refusal therefore shows a review that cannot be one piece, while an estimate inside the ceiling does not prove one.
- Out of scope: Refine, the Shaper's prompt and goldens, kogen-review, kogen-build and kogen-loop; creating the other Intents of a split.
