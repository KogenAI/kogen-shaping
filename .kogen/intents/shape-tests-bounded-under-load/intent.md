# Bound the shape package tests under load

Slug: shape-tests-bounded-under-load
Model: not applicable — a test-only change of timing in the shape package tests; no product state or interacting rules change
Acceptance:
- .kogen/intents/shape-tests-bounded-under-load/acceptance.feature
- features/steps/shape-tests-bounded-under-load__steps.js

The shape package tests are too slow and too load-sensitive to pass inside the Build verification bound, so every kogen-shaping Build since 06:55Z on 18 Nov ended `build:failed host_or_base_failure` although main itself is green. The Build runs `go test ./...` with a 10 minute timeout, and `go test ./...` takes 369 s on a quiet Linux host (shape package 362 s), 543 s on a loaded host (shape 542 s); under Build load the shape package passes the 600 s package timeout and panics with `test timed out after 10m0s`. The summed run time of its tests is about 750 s, so it already depends on t.Parallel. The slowest tests take 10 to 18 s each (TestShapeFeasibilityFitsLimit, TestShapeForceNoToolBound, TestContractCheckExternalShape, TestShapeAcceptanceFitsLimit). Under load these fail on wall-clock assertions: static_overlap_test.go ("independent two-second waits took 3.769431917s" in TestStaticChecksOverlapModelChecks), unpassable_test.go (TestUnpassableControlSkipped, the 2-second and 120-second control bounds), evidence_test.go ("model_checks_ms 1876, want [300,600)" in TestShapeTimeSplitsChecksByGate).

This change cuts the real waiting in the shape package tests and removes real wall-clock thresholds, without removing any scenario or assertion about behaviour:

1. `go test ./...` on a clean main finishes well inside the 10-minute bound on a loaded host; the shape package takes at most 150 s on a quiet Linux host. The waiting is cut with injected or fake clocks and fake commands in place of real sleeps and real subprocess waits, shared fixtures built once per package, and no repeated full repository setups. No go test timeout is raised and no test is skipped.
2. Tests that assert elapsed time use an injected clock or measure ordering (the checks ran concurrently, the time counted once), not "took less than N seconds" or a real millisecond window. The behaviours they cover stay asserted: the static checks overlap the model checks; an unpassable control run is skipped at its bound; the shaping time line splits checks by gate and counts overlap once.
3. No product behaviour, flag, setting or environment variable changes. Only test code and the minimum test-only seams (an unexported clock or runner variable) change. kogen-coordinator, kogen-setup, kogen-loop and the kogen CLI are not changed.
4. The Build decision states the shape package time before and after, measured on the same host, and the slowest ten tests.

No shape test waits on the real clock for more than one second through the test helpers. The acceptance scans refuse any `time.Sleep` call, any shell `sleep` of more than one second and any node timer of more than 1000 ms in `shape/*_test.go`, including inside strings, so a test file must not spell such a command even in a message.

The existing tests stay with their names. The Build adds `shape/clock_bound_test.go` with these model-free unit tests, run by `go test ./shape -run TestClockBound`:
- `TestClockBoundStaticChecksOverlap`: two static checks that each wait two seconds on the injected clock are started together and the run ends after two injected seconds, not four, whatever the real time taken.
- `TestClockBoundUnpassableControl`: an unpassable control run that exceeds its bound on the injected clock is recorded as skipped with the bound named, and a step file that does not load reports its own reason, with no real waiting.
- `TestClockBoundTimeCountsOverlapOnce`: the shaping time line for a gate with overlapping decision and literal checks counts the overlap once, asserted on injected durations.
- `TestClockBoundNoRealSleepsInShape`: fails when a shape test calls time.Sleep or waits longer than one second through the test helpers.
