# Count only the package in Shape's scope gate

Slug: k-shape-scope-gate-counts-package
Model: not applicable — one deterministic, stateless estimate inside the existing submission loop; the refusal reuses the existing refusal record and bounded correction loop
Acceptance:
- .kogen/intents/k-shape-scope-gate-counts-package/acceptance.feature
- features/steps/k-shape-scope-gate-counts-package__steps.js
- features/steps/k-shape-scope-gate-counts-package__harness.js

Today Shape's scope gate (`shape/scope.go`, run by `checkSubmission` after the package is written and formatted and before the decision check) estimates one review of a candidate as the package's own bytes plus the full size at HEAD of every tracked file the Intent names in backticks, and refuses the candidate when that sum is over `tools.InputBudgetBytes`, kogen-loop's `provider.InputBudgetBytes`, the review stage's bound (evidence: `TestScopeBoundIsTheReviewStagesSetting` in `shape/scope_test.go` asserts its compiled value is 524288 bytes). Review never reads those named files whole: it reads the package, the check results, the diff of changed files and the full text of added ones. So a small Intent that merely names a large existing file is refused for bytes review never reads.

After this change the scope gate's estimate of a unit is exactly the sum of the Intent package bytes: intent.md, every path under `Acceptance:` in listed order, and the model file when the Model line declares one, each counted as the byte length of its written, formatted content, as today (evidence: `scopeRefusal` in `shape/scope.go` reads each of these paths once, skipping a repeated path through its seen set). The size at HEAD of a named file no longer counts in any estimate. Nothing else about the gate changes:
- Bound: `tools.InputBudgetBytes` as compiled in, the same shared constant the review stage uses; no copied value, no new setting, flag or knob. Inclusive: an estimate equal to the bound fits, one byte more is refused.
- Refusal: for each unit over the bound, in order, the unchanged unit line `Scope check: <unit> is estimated at <E> bytes of one review (scenarios <S>, acceptance harnesses <H>, named files <F> in areas <A>), over the <L>-byte bound of one review (tools.InputBudgetBytes).` followed by one item line per Intent package file, `- <path>: <n> bytes (Intent package)`, in the order above; after all units, the unchanged guidance line (`scopeGuidance`, byte for byte). <E> is now the package sum. <S> counts the scenarios `project.CheckIntent` returns (an outline counts once per Examples row) and <H> the `Acceptance:` paths other than the feature, as today.
- Named files are still identified by the existing rules (a single-backtick span on one line equal to a HEAD blob path, not under `.kogen/`, not an Intent package path, once each in first-appearance order; a path not at HEAD is not counted), and <F> and <A> still report their count and their distinct directories (`.` for the root). Only their bytes leave the estimate. The named-file item lines `- <path>: <n> bytes (named file, area <dir>)` are removed, because the item lines list what the estimate sums.
- Units: unchanged. Without a `## Stages` plan the unit is `the Intent`; with a valid plan there is one unit per stage (`stage "<id>"`), whose <F> and <A> count the named files its goal names plus those no goal names (evidence: `units` in `shape/scope.go`). Each unit's estimate is the same package sum, because `scopeLines` in `shape/scope.go` starts every unit's estimate from the whole package's bytes and only the named-file term varied per stage.
- Refusal path: unchanged. `submission_refused` with gate `scope` and the result's lines as problems, an invalid outcome, the existing `Unchanged:` note for an identical package, no decision check, literal check, contract check or readiness for a refused candidate, and the existing `intent/not_ready` end (exit 1) when the correction allowance runs out. A candidate inside the bound keeps today's route (evidence: `scopeLines` in `shape/scope.go` returns nil when every unit fits, and `scopeRefusal` then records nothing and returns not refused).

Removed: the named-file term of the estimate and the named-file item lines. Not changed: the Shaper's prompt, policy and tool definitions (shape/prompts and the goldens `shape/testdata/shaper_policy_golden.json`, `prompts_golden.json`, `defs_golden.json` and the force goldens stay byte-identical; do not regenerate them), the staged-plan format, the other gates and their order, Refine, approval, the review stage and the Build.

Build notes:

Do not create that path, and do not use the `kgp` or `KShapeScopeGateCountsPackage` identifier prefixes in the package.

## Decisions
- The scope gate counts the package bytes, which is what review reads, and not the full HEAD size of the files the Intent names. (source: request)
- The bound stays the same shared constant the review stage uses, with no new setting and no knob. (source: request)
- A package whose own text is over the bound is still refused, with the same refusal line and the same record before the decision check, and shaping ends not_ready as before. (source: request)
- The delivered scope tests that encode the named-file sum are updated in the same change; a test that only pins the named-file sum is rewritten to pin the package-only count, not deleted, unless it has no remaining behaviour to pin. (source: request)
- The scope gate's estimate becomes the Intent package bytes only; named files keep their count and area count in the unchanged unit line, their item lines are removed, and the guidance line stays byte-identical. (decision: D1, round 1) (constraint: Bound stays tools.InputBudgetBytes, inclusive) (constraint: Refusal path (submission_refused gate scope, Unchanged note, intent/not_ready) unchanged) (constraint: Shaper prompts and goldens unchanged) (evidence: shape/scope.go; shape/scope_test.go; shape/shape.go) (source: request)
- Acceptance and the rewritten not_ready scope test drive the external scripted shaper (useExternalShape, shapeExec, shapeWith) for packages near or over the bound. (decision: D2, round 1) (evidence: shape/lineup_shape_test.go; shape/helper_test.go; shape/stepownership.go) (assumption: The edge case's route after the 524288-byte candidate passes the gate (a readiness environment stop in the fixture) is observed but not asserted.) (source: request)
