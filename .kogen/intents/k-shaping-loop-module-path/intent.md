# Require kogen-loop by its real module path

Slug: k-shaping-loop-module-path
Model: not applicable — a dependency pin and import-path change with no state or interacting rules
Acceptance:
- .kogen/intents/k-shaping-loop-module-path/acceptance.feature
- features/steps/k-shaping-loop-module-path__steps.js
- features/steps/k-shaping-loop-module-path__checks.js
- features/steps/k-shaping-loop-module-path__control.js

kogen-loop now declares its real module path, `github.com/KogenAI/kogen-loop` (L-MODULE-PATH, landed), and kogen-coordinator, kogen-executor and kogen-verification have each landed their own loop-module-path change on main. kogen-shaping still requires the bare `kogen-loop` through `kogen-loop v0.0.0` plus `replace kogen-loop => github.com/KogenAI/kogen-loop v0.0.0-20261102055344-c6e2360290d4`. This change makes kogen-shaping require `github.com/KogenAI/kogen-loop` directly, moves the three other Kogen components to their current main in the same change, and imports kogen-loop's packages by the real path, so that no module in the build list is or imports the bare `kogen-loop`. kogen-shaping's own behaviour does not change.

What the Build does:

1. go.mod and go.sum. Remove the `kogen-loop v0.0.0` requirement and the `replace kogen-loop => ...` line, then run, in this order:
   `go get github.com/KogenAI/kogen-loop@31036b2c02e8d8b672c3eda0501d37a3e075f60e github.com/KogenAI/kogen-coordinator@e7bc7ce9c169d4dc0fbc93023db0b326d143c634 github.com/KogenAI/kogen-executor@8d465842f9dfe0be2a8cafac1c3d4199a26c223b github.com/KogenAI/kogen-verification@ac4f6a9a4877adc4acaf3c207f97604715299b3b`
   (each SHA is that repository's `refs/heads/main`, read with `git ls-remote` on 2026-11-05), rewrite the imports (step 2), then `go mod tidy`. The result requires exactly, as direct requirements and in this order: `github.com/KogenAI/kogen-coordinator v0.0.0-20261105022408-e7bc7ce9c169`, `github.com/KogenAI/kogen-executor v0.0.0-20261105010505-8d465842f9df`, `github.com/KogenAI/kogen-loop v0.0.0-20261105005409-31036b2c02e8`, `github.com/KogenAI/kogen-verification v0.0.0-20261105003813-ac4f6a9a4877`; go.sum holds the `h1:` and `/go.mod h1:` lines of those four versions; there is no replace directive and no go.work. `go 1.27.2` stays.
2. Imports. Every `"kogen-loop/<pkg>"` import in a .go file becomes `"github.com/KogenAI/kogen-loop/<pkg>"` (packages used: `provider`, `sys`, `tools`); run the configured fix `gofmt -w .` so the import blocks stay sorted. The same rewrite applies to the Go sources that step harnesses embed or ship: the `.js` and `.go.txt` files directly under `features/steps/` (for example `k_shape_time_test.go.txt`, `k-shape-wrong-implementation__harness.js`, `k-consumes-shaping__fixtures.js`).
3. Remaining references to the bare module path, so they keep working without a replace: `features/steps/k-shape-size-for-one-review__steps.js` locates the module with `go list -m -f '{{.Dir}}' github.com/KogenAI/kogen-loop` and, instead of rewriting a `replace kogen-loop` line, gives its private go.mod the line `replace github.com/KogenAI/kogen-loop => <copy>`; `features/steps/k-consumes-shaping__control.js` maps the producer `kogen-loop` to `github.com/KogenAI/kogen-loop`; `consumes/kogen-loop/README.md` (module statement, package names, and the observer command's `kogen-loop=github.com/KogenAI/kogen-loop`), `consumes/kogen-coordinator/README.md` (`github.com/KogenAI/kogen-loop/sys`) and the comment in `shape/policy.go` name the real path. Historical `.kogen/intents/*/` records are not edited.
4. Tests that pin what the upgraded producers do. The new versions change producer-owned behaviour that kogen-shaping's tests observe. With steps 1–2 applied, `go build ./...` and `go vet ./...` pass with no production change, while these tests failed (observed in a scratch copy, before any test change): in `shape`: TestShaperPolicyGolden and TestShapeForceWireCompatibility (kogen-loop's list_files and search_text descriptions grew), TestApproveCardOutput and the red-observation Refine tests (verification adds `Failure phase: assertion` lines), TestRefineOriginalReadinessHitRetainsTheRecordWithoutExecution (readiness evidence version 5), TestApproveWithFullAndPrefixHash, TestApproveRepeatedCardsReuseReadinessWithoutExecution and TestPreflight* (coordinator now refuses the fixture title "Fixture intent" because it names the Git user "Fixture"), TestShapeStopsAddEarliestRefusalOnlyWhenItDiffers, TestLoopKnobsShape and TestLoopKnobsRefine (a cut tool result now delivers 12332 bytes); in `consumes/kogen-coordinator` (project.yaml fixtures refused as `environment/project_config_invalid`, intent bullet parsing), `consumes/kogen-executor` (TestExecutorUsage: `executor.Usage` gained `cache_write`), `consumes/kogen-loop` (TestDefinition, TestCut, TestToolsRepo) and `consumes/kogen-verification` (TestReadinessRedObservations). `contract` and `cmd/kogen-shape` passed. Update those tests, fixtures and the consumes suites with their README inventories so they state what the pinned producers do and what kogen-shaping relies on from them now; keep each test's purpose, keep kogen-shaping's own settings, prompts, tool names and values, and do not change production code to restore an old producer behaviour. Regenerate goldens with `go test ./... -update` only for differences that come from the pinned dependencies, and inspect the diff: `shape/testdata/shaper_policy_golden.json` then differs only in the list_files and search_text descriptions (SHA-256 98c842c3fb874fc529e08dd3d0c1617575c974a1965c0924b3769061aa7e1e9c), and `prompts_golden.json` and `defs_golden.json` stay byte-identical.

Out of scope: any other change to shaping, refinement or approval behaviour; other Kogen repositories; kogen-review, kogen-build and kogen-setup.
