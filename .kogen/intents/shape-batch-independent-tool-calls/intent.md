# Batch independent shaping tool calls

Slug: shape-batch-independent-tool-calls
Model: not applicable — the change schedules the calls of one response and remembers read results within one working window; the executable scenarios observe each rule directly
Acceptance:

Native Shape spends most of its time on model round trips while the shaper makes one tool call per turn. This change tells the shaper to request every independent read, search and probe it needs in one response and not to re-read a file it has already read unless it changed; runs the read-only calls of one response (read_file, search_text, list_files) concurrently with their results returned in the original call order; keeps probes, propose_files and submit running one at a time in call order; and answers a repeated read_file whose result is unchanged within the same working window with a short note instead of the content.

Put the concurrency and the repeat-read check in a new small file shape/batch.go and keep shape/shape.go changes to the call site, the loop over one response's calls in the native conversation. Refine, the external shaping session, provider transport and the kogen-loop tool implementations are unchanged. What is replaced: native Shape no longer runs consecutive read-only calls strictly one after another, and no longer repeats the full content of an unchanged read in the same window. Nothing else is removed.

The controls.json correct implementation is a bounded proof artifact, not a recipe: to fit the control byte budget its shape/shape.go is a reduced copy without comments or indentation, with a minimal conversation loop and panic stubs for routes the scenarios never reach, and it adds the batching sentence to the tool descriptions through a helper instead of ShaperToolDefinitions. The delivered implementation keeps every production behavior, changes ShaperToolDefinitions itself and passes the whole shape package tests.

## Decisions
- In native Shape, each maximal run of consecutive read_file, search_text and list_files calls in one response runs concurrently, with no worker limit, and its results are added to the conversation in call order; every other call, including probe, propose_files, submit, documentation and view_image, runs alone in call order after everything before it finished and before anything after it starts. (decision: D1, round 1) (constraint: Shared shaping state is updated only after a group's calls returned, in call order, so go test -race stays clean.) (constraint: Calls after a counted submit in the same response still answer ignored: only one submit counts per response and do not run.) (evidence: shape/shape.go) (source: request)
- A read_file result is replaced by already read in this window, unchanged (<bytes> bytes, sha <8 hex>) when an earlier read_file of the same cleaned path with the same start_line and end_line arguments in the same working window returned exactly the same result text; <bytes> is the byte length of that text and <8 hex> the first 8 lowercase hex digits of its SHA-256, and any other read returns its normal result and becomes the remembered result for those arguments. (decision: D2, round 1) (constraint: Results that begin with error: are never replaced and never remembered.) (constraint: A working-window reset forgets every remembered result.) (constraint: The note has no trailing period or newline.) (evidence: shape/shape.go; shape/window.go) (assumption: The request leaves open whether the bytes and sha describe the file or the earlier result; they describe the result text the shaper already received, and the same line range is the unit of repetition.) (source: request)
- The repeat check changes only what the model receives: the read still counts as inspection and as a read of its path, and the shaping's retained read text for that path keeps the full result that decision and question checks use. (decision: D3, round 1) (evidence: shape/shape.go; shape/ledger.go) (source: request)
- shape/prompts/shaper.md and the shaper's tool descriptions carry one exact batching sentence: shaper.md gains it as its own bullet directly after the bullet that begins with Read the project with read_file, and ShaperToolDefinitions appends one space and the sentence to the read_file, search_text and list_files descriptions and to the shaper's probe description; the sentence is: Request every independent read_file, search_text, list_files and probe call you need in one response, and do not re-read a file you have already read unless it changed. (decision: D4, round 1) (constraint: Refine's prompt and RefineToolDefinitions stay unchanged.) (constraint: The policy goldens shape/testdata/shaper_policy_golden.json, shape/testdata/prompts_golden.json and shape/testdata/defs_golden.json are regenerated with go test ./shape -update as a deliberate, reviewed policy change.) (evidence: shape/policy.go; shape/policy_test.go; shape/prompts/shaper.md; README.md) (assumption: The exact wording of the sentence is chosen by shaping; the request only says what it must tell the shaper.) (source: request)
- Only the native Shape conversation changes; the external claude-code shaping session and Refine keep their current tool execution. (decision: D5, round 1) (evidence: shape/shape.go) (assumption: The request names the loop in shape/shape.go; Refine's own loop stays sequential.) (source: request)
- Acceptance injects features/steps/shape-batch-independent-tool-calls__driver/cases.go as shape/accept_batch_independent_test.go into a disposable copy of the candidate and runs its tests with go test -json through the real Shape entry point and the existing scripted provider; slow reads are FIFOs under the fixture's ignored .kogen/local folder, so no production test seam is added. (decision: D6, round 1) (constraint: The Build never creates shape/accept_batch_independent_test.go and declares no identifier beginning with acceptBatch or TestAcceptBatch in package shape.) (constraint: The scripted provider fixture, newShpFx, responsesWire, shpCall and shpScopedIntentMD keep their current signatures and behaviour.) (evidence: shape/helper_test.go; shape/force_wires_test.go; features/steps/shape-bounds-tool-free-answers__driver/run.js) (source: request)

## Source comparison
- Addressed, request Change 1: D4 fixes the sentence, its place in shaper.md and the four tool descriptions; scenario "The shaper is told to batch independent calls" checks shaper.md, the instructions sent to the provider and the read_file, search_text, list_files and probe descriptions sent to the provider.
- Addressed, request Change 2: D1 and scenarios "Read-only calls of one response overlap and answer in call order" and "Probes stay in order around a concurrent read group". Grouping consecutive read-only calls keeps every call that precedes or follows a probe, proposal or submit on its side of it.
- Addressed, request Change 3: D2 and D3 and scenario "An unchanged repeat read in the same window answers a short note", with the requested literal note form. The request's "changed by a proposal" is exercised through the proposal custody file that propose_files rewrites under .kogen/local/shaping/<slug>/proposed/, which read_file can read.
- Addressed, file placement: new shape/batch.go holds the concurrency and the repeat-read check; shape/shape.go changes only at the call site. The tool descriptions live in ShaperToolDefinitions, which the existing policy request test requires the provider request to match.
- Addressed, tests first: the four requested failing regression tests are the first four Tests lines, and "Run the shape package tests" is the last one.
- Context, not a threshold: the 11 November 2026 observation with kogen v0.1.0-dev.3c70abcb, studio-concise-agent-intake on chatgpt making one tool call in 123 of its 125 turns, 45% of turns read_file, search_text or list_files and 37% probe, 6-11 s per turn with 3-5 s to first byte, 25-45 minutes per 125-request shaping, and 25 of 46 and 16 of 38 read_file calls re-reading a file, motivates the change.
- Omitted: no worker limit, setting, provider or Refine change; documentation and view_image keep running one at a time because the request names only read_file, search_text and list_files as read-only.

## Tests
- Read-only calls of one response run concurrently and answer in call order: add a regression test whose fake shaper response has three read_file calls and one search_text; all four run, the results come back in call order, and the reads overlap, each read being a FIFO under the fixture's ignored .kogen/local folder whose writer waits 50 ms so the three reads finish in well under 200 ms (regression)
- Probes stay one at a time in call order around read groups: add a regression test whose response has a read_file and a probe; the probe runs after the read and never concurrently with another probe (regression)
- An unchanged repeat read in the same working window answers the note and a changed file is returned again: add a regression test where a second read_file of an unchanged path answers the note and, after propose_files changes the proposal custody file, the next read returns its content (regression)
- The shaper is told to batch: add a test that shape/prompts/shaper.md and the read_file, search_text, list_files and probe definitions from ShaperToolDefinitions contain the batching sentence (unit)
- A working-window reset forgets earlier reads: add a unit test of the batch.go read memory showing that the first read after a reset returns the content (unit)
- The policy goldens record the deliberate policy change: regenerate the three goldens named in D4 with go test ./shape -update and review the diff (existing)
- Surrounding shaping behavior is preserved: run go test ./shape, updating only expectations of existing tests that relied on a repeated unchanged read returning its content (existing)
