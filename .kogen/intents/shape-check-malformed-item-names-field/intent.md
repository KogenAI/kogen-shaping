# Name malformed checker items and fields

Slug: shape-check-malformed-item-names-field
Model: not applicable — these pure parsers change diagnostics only, with no meaningful state or transition
Acceptance:

Make malformed-item feedback from parseLiteralCheck in shape/literal.go and parseDecisionCheck in shape/decision.go actionable: identify the first malformed item, its first problem, and the total malformed-item count when multiple items are malformed. Replace the generic item error text only. Do not change accepted inputs, schemas, checker instructions, draft eligibility, or published results. Implementation scope is the two parse functions plus focused model-free Go regression coverage in the shape package; no browser, Rails, Studio, provider calls, new settings, or validation rules.

## Decisions
- Use one-based item positions in both parsers and report the earliest malformed item in input order. Count malformed items, not problems; append the total in parentheses only when more than one item is malformed. (source: request)
- Report required fields in their existing schema-required order: literal, source, source_quote, package_value, why, status for literals; statement, request_quotes, verdict, intent_value, request_value, difference, why for decisions. Distinguish a missing field from a wrong type. After required-field checks, report the lexicographically first unknown field; after that, check the status or verdict enum. This defines a deterministic first problem without changing validity. (evidence: shape/literal.go; shape/decision.go) (source: request)
- Identify non-object items and malformed request_quotes with their item position too. Keep the existing top-level payload checks, error class, reason, exit value, and surrounding invalid-payload envelope, including nothing was published. Preserve all successfully parsed values and order, including empty strings, empty lists, all allowed literal statuses and all allowed decision verdicts. Decision items have verdict, not status; their unknown-enum diagnostic names the allowed verdicts. (evidence: shape/literal.go; shape/decision.go; shape/literal_test.go; shape/decision_test.go) (source: request)
- Drop the old an item is malformed wording for these two parsers: their existing tests check the error envelope rather than that generic detail. Leave question-check diagnostics and tests untouched. (evidence: shape/literal_test.go; shape/decision_test.go; shape/question_test.go) (source: request)
- Add focused model-free regression assertions to TestParseLiteralCheck and TestParseDecisionCheck, retaining their useful existing cases. Acceptance also runs the supplied TestMalformedLiteralItemDiagnostics and TestMalformedDecisionItemDiagnostics through a Go build overlay in package shape, along with the corresponding existing named parser test. These supplied tests exist before Build; acceptance must verify each named test and supplied subcase actually ran and passed, not infer test presence from Git or file listings. (evidence: shape/literal_test.go; shape/decision_test.go; .kogen/project.yaml) (source: request)

- Missing fields identify the first item and field: extend TestParseLiteralCheck and TestParseDecisionCheck and run the supplied diagnostic tests against the reproducing omitted-field payloads (regression)

- Existing malformed categories receive actionable first-problem feedback: run wrong-type, unknown-field, non-object and malformed request_quotes cases in the named diagnostic tests (unit)
- Multiple malformed items report the first item and total item count: run multi-item cases with deterministic required-field and unknown-field ordering (unit)
- Valid items parse unchanged: compare complete parsed values for all allowed enum values, empty strings and empty lists, and retain the existing parser tests (regression)
